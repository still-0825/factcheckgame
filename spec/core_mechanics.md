# ゲーム仕様書：コアメカニクス詳細

本ドキュメントでは、ファクトチェックADVゲーム「FactChecker（仮）」のコアメカニクス（基本システム）について定義します。

---

## 1. コアメカニクス概要

本ゲームは以下の4つのフェーズをサイクルとして進行します。

```
[情報入手] ──> [ゲーム内ブラウザ検索] ──> [証拠ボード確認] ──> [推理・矛盾指摘]
```

### 1.1 情報入手 & 吟味（フェイクニュースの特定）
- **概要**: プレイヤー（普通の高校生「レン」）は、ゲーム内のSNSタイムライン、チャットログ、オリジナルデザイン of ニュースサイトなどから、不審な情報（フェイクニュースの疑いがあるもの）を発見します。
- **キャラクターによる操作解説・チュートリアル**:
  - 主人公の行動やファクトチェック業務を、サポートキャラである幼馴染の「アオイ」が会話を通じてアシストします。
  - 第1章（チュートリアル）では、アオイが会話ウィンドウを通じて「この単語をクリックして検索してみよう」などの基本操作をステップバイステップで親切に解説します。

### 1.2 ゲーム内検索システム（キーワード選択形式・オリジナルWeb風）
- **概要**: プレイヤーがゲーム内のモックアップブラウザを使用し、ファクトチェックを行うための検索を行います。
- **メカニクス**:
  - **キーワードクリック検索**:
    - プレイヤーは、ゲーム内の記事や会話テキストに存在する「単語」をクリックして、ブラウザの検索窓にセットし、検索を実行します。
    - **「ノーヒント設計」 (確定仕様)**: 検索可能なワードと、検索しても有力な情報が出ないワード（普通のワード、ダミーなど）との間に、**見た目上の違い（下線、色変化、ハイライト、ホバー時のカーソル変更など）は一切設けません。** カーソルを重ねても標準のテキスト選択カーソルのままであり、ホバーエフェクトも発生しません。プレイヤー自身が「検証に必要か」を純粋に論理的思考で判断します。
    - 中高生でも「怪しい単語はどれか」を少し考えれば推測できる範囲にし、大人でも「なるほど、この単語がキーワードになるのか」と納得できる絶妙な語彙を選定します。
  - **オリジナルWeb風の検索結果と証拠獲得**:
    - 既存の特定の検索エンジンやWebサイトを模倣せず、本作独自のデザインを施したオリジナルWebサイト（専門機関、公的統計、ブログなど）が検索結果として表示されます。
    - 検索結果のページ内にある特定のキーワードをクリックすることで、**「証拠（ファクト）」**を獲得できます。
    - **訪問済みリンクの可視化**: プレイヤーが過去に訪れた（クリックして開いた）ことのあるWebページのタイトルリンクは、一目で識別できるように**紫色**に変化します（未訪問のページは水色）。これにより、「どの情報をすでに調査したか」が直感的に分かり、探索の重複を防ぎ、プレイ時の迷いを軽減します。

### 1.3 証拠ボード（Evidence Board / 閲覧・確認システム）
- **概要**: プレイヤーが手に入れた「フェイクニュースの疑いがある記事」と「ブラウザ検索で得た客観的事実（ファクト）」を視覚的に整理する画面です。
- **演出の流れ**:
  1. **会話の発生（トリガー）**:
     - 特定の2つ以上の証拠が獲得された瞬間、まずはレンとアオイの「掛け合い会話（ストーリー）」が開始されます。情報がどのように繋がっているか、何が矛盾しているかをアオイが論理的に整理してくれます。
  2. **ボード画面への切り替え**:
     - 会話終了後、画面が自動的に「証拠ボード画面」に切り替わります。
  3. **付箋の貼り付け演出**:
     - 新たに獲得した証拠カード（付箋）が、コルクボードの上に「ペタッ」と実際に貼られるような、アニメーション演出が再生されます。
  4. **関係性ラインのフェードイン**:
     - その後、関連する付箋同士を結ぶ「関係性ライン（糸）」がゆっくりとフェードインする形で表示されます。
- **関係性の視覚表現（色分けと文字ラベル）**:
  - ラインは関係性ごとに一目で識別できるよう、明確に色分けされ、さらにラインの直上に関係性を示す文字（テキストラベル）が表示されます。
    - **矛盾関係（例：赤色のライン + 「矛盾」）**
    - **裏付け関係（例：緑色のライン + 「裏付け」）**
    - **関連・補足（例：青色のライン + 「補足」）**
- **プレイヤーの役割（閲覧・確認専用）**:
  - プレイヤーはボード上の配置換えや手動配線は行わず、整理された内容を論理的に読み解くための「確認用ツール」として活用します。

### 1.4 推理・矛盾指摘パート（ライフ制 & アシストシステム / 確定仕様）
- **概要**: 偽の情報を拡散している相手（または誤解している人物）と対峙し、真実を突きつけて矛盾を暴く対決パートです。
- **メカニクス**:
  - **論戦・矛盾の指摘 (2ステップUI方式)**:
    1. **ステップ1：相手の発言（主張テキスト）の選択**: 相手が1〜3文の主張を提示してきます。これらはそれぞれ個別の選択可能なテキストボックスになっており、プレイヤーは矛盾していると思う相手の発言（文）をクリックして選択状態にします。
    2. **ステップ2：証拠付箋の選択・提示**: 画面下部に表示される、これまでに獲得した「証拠付箋」の一覧から、矛盾を証明できるファクト付箋を1つ選択し、「突きつける（決定）」ボタンを押します。
  - **ライフシステム（ライフ：3）**:
    - プレイヤーには **「3つのライフ（論理HP / 信用度）」** が与えられます。
    - 誤った証拠を突きつけたり、矛盾していない発言を指摘したりすると、ライフが1減少します。
    - ライフが0になると「説得失敗（ゲームオーバー）」となり、その対決の最初からやり直しになります。
  - **アオイのアシスト（救済システムと演出の流れ）**:
    - プレイヤーが誤った選択をしてライフが3から「2」に減少した（1回目のミスをした）際、以下の流れでアシストが発生します。
      1. **不正解演出**: 不正解であることを示す画面エフェクト（バツマーク等）が表示され、不快すぎない適切な警告音（SE）が流れます。
      2. **画面切り替え**: 推理画面から「アオイの会話画面」へとフェードインで切り替わります。
      3. **柔らかいアドバイス（セリフ）**: アオイは焦る様子を見せず、柔らかくレンを導くようにアドバイスをくれます。
         - **アオイの台詞例**:「レン、焦らなくて大丈夫だよ。一度落ち着いてみよう。相手のさっきの発言、私たちが集めたあの証拠と食い違っているところがないか、もう一度よく見比べてみて？」
      4. **推理画面への復帰**: 会話終了後、元の推理画面に戻り、ゲームが再開されます。これにより、中高生や普段ADVをやらない人でも詰まることなく最後まで楽しめるバランスを維持します。

### 1.5 進行管理システム（章クリア選択と章選択）
- **章クリア後の選択**: 各章のエピローグ（会話パート）がすべて完了した際、ゲームは直接次の章に進むのではない、「次の章（CHAPTER_INTRO）へ進む」か「タイトル画面（TITLE）に戻る」かを選択できるクリア選択UI（`CHAPTER_CLEAR_CHOICE`）を表示します。
- **クリア状況の永続化**: 章をクリアするたびに、次にプレイ可能な最大章（`maxUnlockedChapter`）が自動的に `localStorage` に保存され、ブラウザを閉じても進捗が保持されます。
- **章選択（チャプターセレクト）**: プレイヤーが第1章をクリアした後にタイトル画面の「PLAY GAME」をクリックすると、直接1章が始まるのではない「章選択画面（`CHAPTER_SELECT`）」が表示されます。プレイヤーはこれまでにクリアした章（および現在挑戦可能な最新の章）を選択して、任意の章からゲームを開始できます。未開放の章はロック（グレーアウト・鍵表示）され、選択できません。

## 2. プレイヤーへの教育的フィードバック（解説シート）

各ステージをクリア（推理に成功）した際、プレイヤーには以下の「解説シート」を表示します。
中高生に向けて言葉は優しく表現しつつ、大人が読んでも「勉強になった」と思える深いリテラシー知識を伝授します。

- **実在の事例モデルの紹介**:
  - 今回解決した事件のモデルとなった、実在するフェイクニュースやデマの事例を分かりやすく紹介します。
- **だまされないためのテクニック（実践知識）**:
  - 「情報発信元のプロフィール欄を確認する」「検索エンジンを使って一次データにあたる」「画像を逆検索する」といった、日常生活ですぐに実践できる具体的なメディアリテラシー技術を学習シートとして提示します。

## 3. サウンドシステム仕様（WAVループ再生方式）

本作は、プレイヤーの没入感と教育的な緊張感を高めるため、外部音声リソース（WAVフォーマット）を動的にロード・ループ再生する効率的なBGM管理システムを搭載しています。

### 3.1 外部BGMファイル（WAV）の非同期ロードとループ再生
ゲーム独自の雰囲気をより高い音色と一貫性で表現するため、従来のプロシージャル（即興演奏）シンセサイザー方式を廃止し、専用のBGM素材（`/assets/bgm/bgm.wav`）を再生する仕組みへと移行・統合しました。

1. **非同期フェッチ & デコード**:
   - Web Audio APIの `AudioContext` を使用。ゲーム開始時（またはミュート解除時）に非同期で `fetch` を行い、`decodeAudioData` を通してブラウザのメモリ上に `AudioBuffer` として展開。ネットワーク帯域や初期ロード時の負荷を最小限に抑えます。
2. **AudioBufferSourceNode による高精度ループ**:
   - ループ再生はWeb Audio API標準の `loop = true` プロパティを活用し、ブラウザスレッドの影響を受けることのない継ぎ目のないループ再生を実現しています。

### 3.2 ゲーム状態の同期とシームレスな再生
- **シームレス設計**: BGMは状況に応じた曲の切り替えではなく、一本の環境WAVファイルを永続的にループさせる設計に移行しました。これにより、シーン遷移や検索フェーズ、推理対決パートなどの画面切り替え（GameStateの変動）が発生した際も、音楽がぶつ切りに途切れることなく、自然で没入感のあるプレイを継続できます。
- **インターフェース互換性**: 既存のゲームシステム（Reactコンポーネント側）との互換性を保つため、`setBgmMode` などの呼び出し口は維持され、無駄なエラーを防いでいます。

### 3.3 ユーザフレンドリーなサウンド制御
- **初期ミュート設計**: ブラウザの自動再生ポリシーを考慮し、またプレイヤーの意思を尊重するため、ゲーム開始時はBGM・SEともに初期状態でミュート（オフ）に設定されています。
- **トグル制御**: タイトル画面およびゲーム内ヘッダーに配置されたスピーカーボタンから、いつでも瞬時にミュート切り替え（BGM再生の開始・停止および音量コントロール）が可能です。
- **音量バランス**: WAVファイルの持つ周波数帯域や音圧を考慮し、他の効果音（クリック音や正解・不正解のSE）の聴き取りやすさを邪魔しない範囲で、十分に聴き取りやすい適正レベル（0.85）に調整されています。

### 3.4 今後の検討・議論・質問事項（開発引き継ぎ用）
1. **BGM（bgm.wav）のクオリティと音量感について**:
   - BGMをWAVファイルのループ再生方式に変更しました。ゲーム全体の雰囲気とbgm.wavの音楽的な調和、および効果音との音量バランスはいかがでしょうか？
2. **SE（効果音）の外部ファイル化について**:
   - 現在、正解音や不審な点に気づいたときのSEはWeb Audio APIのオシレーター音（矩形波やサイン波など）によるシンセ音となっています。これらもBGM同様に外部WAVファイル（/assets/se/等）として実装を変更したほうが良いでしょうか？
